## docs-kit `init` (architecture#6)

architecture#6 is sub-issue E of the docs-site epic (architecture#3):
starting a docs site in a repo that has none. docs-kit#16 added

```text
docs-kit init --repo <name> --title <title> --description <text> --hue <0-359> [--sha <docs-kit sha>]
```

It writes 13 files: `docs-site/`, stub pages under `docs/`, and the two
workflows, `docs-site.yml` (the PR check) and `deploy-docs.yml` (whose paths
include `sdk/include/**`). The palette is derived from the hue. The pinned
docs-kit SHA defaults to the release's own, found with `git ls-remote`. Files
are written exclusively (`wx`), so `init` never overwrites anything, and a
failure part-way removes what it wrote. The title and description must each be
one line. Released as v0.4.0 (docs-kit#17) and checked through `npx`.

scout-drone was the first repo started this way (scout-drone#3). It is ticked
on architecture#6. The issue stays open for isr-drone, nano-drone,
interceptor-drone and counter-uas: each gets one `init` PR, plus Pages switched
on, once it has documents.

## docs-kit v0.4.1: image links

docs-kit#18 fixed a plain link (not an embed) to an image under `docs/`. It
now goes to the file on GitHub, and only images that are actually shown get
copied into the site. Two details:

- Whether `![…](…)` is an embed is decided on the line with its code spans
  blanked, so an image inside backticks is not copied. Escapes are found by
  counting the run of backslashes, so `\\![x](y)` is still an embed.
- GitHub URLs are percent-encoded per path segment. The README now says
  reference-style definitions count as images.

Released as v0.4.1 (docs-kit#19). Every site was bumped to it: synapse#77,
anatomy#27, racing-drone#85, cortex#553, scout-drone#11 (all merged by the
user, since they touch `.github/workflows`) and reflex#67. Each deploy was
checked live.

## The license ADRs

The user asked why synapse and reflex had no counterpart to cortex's license
ADRs, and said the policy "needs to be recorded as that is certainly
intended". cortex records it in ADR 0001 (dependency licenses) and ADR 0002
(no GPL, clean-room), with ADR 0006 for its clean-room CV stack. cortex's
ADR 0003, the hybrid SDK design, has nothing to do with licenses and was not
carried over.

- **synapse (#79):** synapse's first ADRs, with `docs/adr/README.md`.
  - **0001**, third-party license compatibility. synapse is MIT. The matrix
    covers MTL5, Universal (tests only), Highway (opt-in, under its BSD-3
    branch), Catch2, the llama.cpp/ggml and YaRN ports, and Unicode data.
    `THIRD_PARTY_NOTICES.md` is the ledger, and model weights stay outside
    the repo.
  - **0002**, no GPL code; port only from permissive sources. synapse ports
    MIT code from llama.cpp on purpose, so this ADR says where that line is.
- **reflex (#70):** the matrix adds mp-dsp (tests only), emsdk and the
  Emscripten runtime libraries linked into the WebAssembly module, and the
  trace player's ajv and three. Its 0002 names the GPL flight stacks
  (Betaflight, INAV, Cleanflight, ArduPilot, Paparazzi) and gives PX4 (BSD-3)
  as the permissive reference.
- **anatomy (#29, ADRs 0002 and 0003), racing-drone (#89, 0009 and 0010),
  scout-drone (#13, its first):** generated from one template. They name the
  UZH GPL-3.0 code (agile_autonomy, rpg_mpc, rpg_quadrotor_mpc,
  rpg_time_optimal) and the permissive references (agile_flight and
  deep_drone_acrobatics, MIT, and PX4). Licenses were taken from GitHub's
  license metadata, not from reading the code. racing-drone and scout-drone
  also add a data rule: third-party datasets and weights only under a recorded
  license, and nothing non-commercial or share-alike.

CodeRabbit's reviews tightened the shared wording, in every repo:

- **Structure allowance:** a GPL project's directory layout and module split
  may be consulted. Its code, algorithm details and data (tuning tables, gains,
  coefficients, weights) may not.
- **Weak copyleft:** LGPL, MPL, AGPL and SSPL are rejected outright. An
  exception needs a superseding ADR.
- **Scope:** what the repo ships, its build and its tests. The docs-site
  toolchain is not part of it.

One finding on scout-drone#13 was a factual error that every repo shared. The
ADRs said "sharp and libvips (LGPL-3.0)". The lockfiles say sharp and
`@img/sharp-<platform>` 0.34.5 are Apache-2.0, and only the prebuilt
`@img/sharp-libvips-*` 1.2.4 binaries are LGPL-3.0-or-later. It was fixed in
the three open PRs, and in synapse (#81) and reflex (#73), which had already
merged.

cortex#556 then amended cortex's ADR 0002 to the same terms. "No GPL contact"
became "No GPL code". It gained the scope rule: read literally, its "not as a
build-time tool" had covered the docs site's libvips. It also gained the
structure allowance and the outright rejection of weak copyleft. ADR 0001's
rejected list gained AGPL. The amendment is recorded in the Status line, as
cortex's ADR 0011 does.
